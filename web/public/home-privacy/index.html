Voor wie zijn huis in het spel wilFor anyone who wants their home in the game

Je huis staat in het spel. Je binnenkant niet.Your house is in the game. Your inside isn't.

De broncode van Brieltje is openbaar: iedereen kan hem lezen. Toch kan niemand de binnenkant van je huis zien zonder jouw code. Niet in het spel, niet in de bestanden en niet met een aangepaste versie van het spel. Op deze pagina zie je precies hoe dat werkt, en je kunt het zelf uitproberen.

Brieltje's source code is public: anyone can read it. Yet nobody can see the inside of your home without your code. Not in the game, not in the files and not with a modified copy of the game. This page shows exactly how that works, and you can try it yourself.

Een brievenbus met een gleufA mailbox with a slot

De verzegeling werkt als een brievenbus. Iedereen kan er een brief in steken: de "openbare sleutel" staat gewoon in de code, zodat wie aan het spel werkt nieuwe gegevens kan verzegelen zonder ooit een geheim te kennen. Maar er is maar één sleutel die de bus opent: de "privésleutel" van de server. Dat zijn 32 willekeurige bytes. Die staan enkel als instelling op de server waarop het spel draait, nooit in de code, in logbestanden of in een verslag.

The seal works like a mailbox. Anyone can drop a letter in: the "public key" is right there in the code, so whoever works on the game can seal new data without ever knowing a secret. But only one key opens the box: the server's "private key". That's 32 random bytes. They exist only as a setting on the server that runs the game, never in the code, in logs or in a report.

Elk bestand krijgt bovendien een eigen, eenmalige sleutel, en de naam van het bestand zit mee in de verzegeling. Wie één byte wijzigt, of twee bestanden van naam wisselt, breekt het zegel: de server weigert het bestand dan. En elk bestand wordt opgevuld tot een veelvoud van 16 KiB, zodat zelfs de grootte niets verraadt over hoe groot je huis is.

Each file also gets a one-time key of its own, and the file's name is part of the seal. Changing a single byte, or swapping the names of two files, breaks the seal: the server then refuses the file. And every file is padded to a multiple of 16 KiB, so even its size says nothing about how big your home is.

Waarom werkt dat? X25519 heeft een wiskundige eigenschap: jouw privésleutel met mijn openbare sleutel geeft hetzelfde getal als mijn privésleutel met jouw openbare sleutel. Wie enkel de twee openbare sleutels heeft, kan dat getal niet berekenen.

Why does this work? X25519 has a mathematical property: your private key with my public key gives the same number as my private key with your public key. Someone with only the two public keys can't work that number out.

De stappen, voor wie het precies wil wetenThe steps, for those who want the details
  1. De opvulling: 4 bytes lengte, de inhoud, dan nullen tot een veelvoud van de blokgrootte (16 KiB op de server, 256 bytes in deze demo zodat je het geheel ziet).
  2. Padding: 4 bytes of length, the content, then zeros up to a multiple of the block size (16 KiB on the server, 256 bytes in this demo so you can see the whole thing).
  3. Een eenmalig X25519-sleutelpaar voor dit ene bestand. Samen met de openbare sleutel van de server geeft dat een gedeeld geheim dat enkel de server opnieuw kan berekenen.
  4. A one-time X25519 key pair for this one file. Together with the server's public key, it gives a shared secret that only the server can work out again.
  5. HKDF-SHA256 maakt van dat geheim een AES-256-sleutel, gebonden aan beide openbare sleutels en aan de bestandsnaam.
  6. HKDF-SHA256 turns that secret into an AES-256 key, bound to both public keys and to the file name.
  7. AES-256-GCM versleutelt de inhoud en maakt een zegel (de tag) over de inhoud en de bestandsnaam.
  8. AES-256-GCM encrypts the content and makes a seal (the tag) over the content and the file name.
  9. Het bestand: "BPD2", de eenmalige openbare sleutel, de nonce, de tag en de versleutelde inhoud. De eenmalige privésleutel wordt meteen vergeten.
  10. The file: "BPD2", the one-time public key, the nonce, the tag and the encrypted content. The one-time private key is forgotten at once.

Hoe lang duurt raden?How long would guessing take?

De server telt elke poging voor hij iets anders doet. Eén afzender krijgt 30 pogingen per uur, en 8 per huis per 10 minuten. Een massa computers samen? Na 300 pogingen per uur voor één huis gaat de rest in een trage rij: ongeveer één per seconde.

The server counts every try before it does anything else. One sender gets 30 tries an hour, and 8 per home per 10 minutes. A crowd of computers together? After 300 tries an hour at one home, the rest go into a slow lane: about one a second.

Gemiddelde tijd om de code te vinden, op een logaritmische schaal: elke streep is tien keer langer dan de vorige. Er zijnAverage time to find the code, on a logarithmic scale: each mark is ten times longer than the one before. There are mogelijke codes.possible codes.

En als iemand massaal foute codes typt om jou buiten te houden? Er is geen slot dat dichtvalt na te veel fouten. Een vloed van pogingen wordt vertraagd, jij kunt het een ogenblik later opnieuw proberen, en wie al een pas heeft, wordt niet vertraagd.

And if someone floods wrong codes to keep you out? There's no lock that snaps shut after too many mistakes. A flood of tries is slowed down, you can try again a moment later, and anyone who already has a pass isn't slowed at all.

Samen spelen: de server beslistPlaying together: the server decides

De belangrijkste regel van het hele spel: de server vertrouwt niets wat een browser hem stuurt. Elke speler krijgt enkel wat die mag zien.

The most important rule of the whole game: the server trusts nothing a browser sends it. Each player only gets what they're allowed to see.

  • De binnenkant wordt nooit naar B gestuurd. Er valt dus niets te ontgrendelen met de ontwikkelaarstools van de browser of een aangepaste versie van het spel: wat je nooit kreeg, kun je ook niet bekijken.
  • The inside is never sent to B. So there's nothing to unlock with the browser's developer tools or a modified copy of the game: you can't look at what you never received.
  • Ook wat er binnen gebeurt, blijft binnen. Deuren, gebroken ruiten en verschoven meubels binnen in je huis gaan enkel naar spelers met toegang.
  • What happens inside stays inside. Doors, broken windows and moved furniture inside your home only go to players with access.
  • Binnenglippen lukt niet. Loopt B door een deur die A openliet, dan weigert de server die positie en zet hij B terug buiten.
  • Slipping in doesn't work. If B walks through a door A left open, the server refuses that position and puts B back outside.
  • Toegang hoort bij je sessie, niet bij je naam. Wie later dezelfde spelersnaam kiest, krijgt niets.
  • Access belongs to your session, not your name. Someone who later picks the same player name gets nothing.
  • Binnen is het veilig. In een privéhuis kan niemand geraakt worden. Die bescherming stopt 30 meter van de kamer, zodat ze geen schuilplaats wordt.
  • Inside is safe. Nobody can be hit inside a private home. That protection stops 30 metres from the room, so it can't become a hiding spot.

VragenQuestions

Kan iemand het versleutelde bestand lezen?Can someone read the encrypted file?

Het staat in de openbare code, maar zonder de sleutel van de server is het ruis. Die sleutel is 32 willekeurige bytes: 2256 mogelijkheden, meer dan er atomen in het zichtbare heelal zijn. Er is geen wachtwoord dat je kunt raden.

It's in the public code, but without the server's key it's noise. That key is 32 random bytes: 2256 possibilities, more than there are atoms in the visible universe. There's no password to guess.

En als de sleutel toch uitlekt?And if the key leaks anyway?

Dan maken we een nieuwe sleutel en verzegelen we alles opnieuw. Oude versies in de geschiedenis van het project blijven wel leesbaar met de oude sleutel. Daarom verlaat de sleutel nooit de server.

Then we make a new key and seal everything again. Old versions in the project's history do stay readable with the old key. That's why the key never leaves the server.

Kan iemand het bestand vervalsen of twee huizen verwisselen?Can someone forge the file or swap two homes?

Nee. Het zegel dekt elke byte en de bestandsnaam. Eén wijziging en de server weigert het bestand. Probeer het hierboven in de demo.

No. The seal covers every byte and the file name. One change and the server refuses the file. Try it in the demo above.

Verraadt de grootte van het bestand hoe groot mijn huis is?Does the file's size give away how big my home is?

Nee. Elk bestand wordt opgevuld tot een veelvoud van 16 KiB.

No. Every file is padded to a multiple of 16 KiB.

Ik ben mijn code kwijt.I lost my code.

Vraag per mail een nieuwe aan. De beheerder maakt er een, en de oude stopt meteen met werken.

Ask for a new one by email. The admin makes one, and the old one stops working at once.

Werkt het ook als ik alleen speel?Does it work when I play alone too?

Ja. Ook alleen vraagt het spel de code, en de binnenkant komt pas van de server als de code juist is.

Yes. Alone, the game asks for the code too, and the inside only comes from the server once the code is right.
