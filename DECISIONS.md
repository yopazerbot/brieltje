# Decisions

What we chose, and why. Newest at the bottom.

| Date | Decision | Why |
|---|---|---|
| 2026-10-28 | **Engine: Three.js with Vite** (from the handover) | Runs in the browser without installs, well known to AI tools, simple to host. |
| 2026-10-28 | **TypeScript instead of plain JavaScript** | The type checker catches mistakes on every build. That matters when nobody reads the code line by line. Three.js ships its own types. |
| 2026-10-28 | **Project folder outside OneDrive**: `C:\Users\YoshiParlevliet\dev\briel-3d` | OneDrive tries to sync every file. A web project has thousands of small files, and sync locks can corrupt git's history. The originals stay untouched in OneDrive. |
| 2026-10-28 | **Backup via private GitHub repo** `yopazerbot/briel-GTA` | Off-site history of every step. Commits use the GitHub "noreply" address so no personal email ends up in the history. |
| 2026-10-28 | **Source copies stay out of git** (`source\` is ignored) | They are private documents and large. Only small derived data (walls, heights) goes into the repo. |
| 2026-10-28 | **Geometry source: the first set of floor plans (Sep 2025)** (Yoshi's choice) | Yoshi named these as the plans to use. Note: newer sets exist (Sep 2025, Feb 2026, the lighting plan of Jul 2026). The most visible difference is a garden shed (tuinberging) under the covered terrace in the newer plans. It also shows in the later reference images. |
| 2026-10-28 | **Heights from the facade and section drawings**: floors at 0, 3.05 and 5.88 m, ceilings at 2.70, 5.53 and 8.41 m | The first set has no level marks. The later drawings differ by 3 cm at most. |
| 2026-10-28 | **Walls read automatically from the vector PDF**, not traced by hand | Vector PDFs store walls as exact shapes. The extractor converts them at 1:75 and lines up the three floor sheets using the section markers. The footprint comes out at 9.00 x 12.02 m, matching the dimensions on the plan. |
| 2026-10-28 | **Hand-measured additions in one file**: `data/house.manual.json` | Glass walls, window heights, stair holes, railings and the garden can't be read reliably from the plan. Keeping them in one file, each with a note, makes every manual choice easy to check. |
| 2026-10-28 | **Own simple collision instead of a physics library** | Every solid is a flat outline extruded between two heights. The player is a 25 cm radius cylinder that can step up 50 cm. It is about 150 lines of code and handles walls, glass, stairs and falling. It is also exact, because drawing and collision use the same blocks. |
| 2026-10-28 | **Sky drawn once into a texture; render at normal resolution** | The sky shader cost about half the frame time on the laptop's integrated graphics. With this change a frame takes 13 to 17 ms (60 to 75 fps) instead of about 42 ms. |
| 2026-10-28 | **Both control schemes always active; the start screen choice sets hints and pause behaviour** | You can pick up the controller at any time without restarting. "Keyboard + mouse" captures the mouse, "Controller" doesn't. |
| 2026-10-28 | **Nickname stored in the browser only** | A stopgap until the login system with user management exists. It will then come from the user account. |
| 2026-10-28 | **Python tools in a project-local environment** (`tools\.venv`) | Nothing is installed system-wide. |
| 2026-10-28 | **Temporary password gate on Railway** (HTTP Basic Auth in a small Node server, scrypt password hash, fail closed) | The custom domain makes the site public. The real login with user management and audit log comes later; this server is the start of that back end. |
| 2026-10-28 | **House data inside the web app** (`web/src/data/house.json`) | Railway builds only the `web` folder, so the app must not read files outside it. |
| 2026-10-28 | **Geometry follows the lighting plan of 7 July 2026** (Yoshi's choice) | Newest drawings. They draw walls as hatched outlines, so the first set's walls stay the extracted base and the changes are manual edits: garden shed, claustra wall at the carport, office 1 wall moved 52 cm, outbuilding left out (later phase). `tools/compare_plans.py` overlays both sets to check. |
| 2026-10-28 | **Real textures (Poly Haven, CC0) and a photographed sky** | Biggest single step towards photorealism without a 3D artist. Downloads approved by Yoshi. Originals stay in `source/`; web copies (WebP, about 6 MB) are in git. |
| 2026-10-28 | **Facade brick generated, light beige** | No library brick matches. The plan legend says light beige blended; size taken from the site photos. Yoshi confirmed beige over the grey seen on overcast photos. |
| 2026-10-28 | **Graphics presets with Auto detection** (Low, Medium, High, Ultra) | This PC's graphics chip is low-end. Auto tests the real scene at start-up and picks the best preset that holds 60 fps; it steps down during play if needed. Choice is remembered per browser. |
| 2026-10-28 | **Real-time ambient occlusion now, Blender light bake next** | Soft corner shadows in real time are expensive on weak chips. A Blender bake stores light (including light bouncing between walls) in textures once, which looks better and runs faster. |
| 2026-10-28 | **No password on the live site, kept out of search engines** (Yoshi's choice, replaces the temporary password gate) | Simplest for family and friends. `noindex` header on every response, robots meta tag and `robots.txt`. Not access control: anyone with the URL can open it. |
| 2026-10-28 | **Interactive sliding doors** (main bedroom glass slider R0.07; entrance hall to bedroom hall, corrected by Yoshi from the WC door) | Yoshi's request. Panels are solid wherever they currently are, so a closed door blocks you. More doors can be added in `data/house.manual.json`. |
| 2026-10-28 | **Explore or Action mode, jumping, Minecraft-style flying, adjustable walking speed** | Yoshi's requests for a playful GTA feel. The pistol, hands and gun sounds are built in code (no downloads); bullet holes stay on the walls (last 80). |
| 2026-10-28 | **Claustra only in front of the sanitary room window** | Corrected by Yoshi: the open brickwork is the outer brick layer in front of window R1.02, not a wall across the carport. |
| 2026-10-28 | **Kitchen and bathrooms from the supplier drawings** (`tools/furniture.py`) | Built as solid blocks with real dimensions: oak tall units with ovens, terracotta island with terrazzo top, walnut double vanity, freestanding bath, walk-in showers with tiles. | 2026-10-28 | **Multiplayer: up to 4 players, accounts, chat, admin** | Yoshi's request. One Node server (WebSocket via `ws`), Railway Postgres for accounts and the login log, admin password from a Railway variable, 3 player accounts made by the admin. Solo play stays open without login. Sessions in HttpOnly SameSite=Strict cookies, origin checks on every API call and the WebSocket, login lockout per IP. |
| 2026-10-28 | **Build tools listed as regular dependencies** | Railway sets NODE_ENV=production; this keeps Vite and TypeScript installed for the build. |
| 2026-10-28 | **Hall sliding door 1.25 m wide; breakable windows** | Yoshi: the thin strip next to the door is part of the opening (it was the door leaf drawn in the plan). Windows are separate meshes so a shot can break one; the gap becomes walkable, broken windows are shared in multiplayer, "Repair windows" in the menu restores them. |
| 2026-10-28 | **One name field for solo and multiplayer; online list; visitor IP from Cloudflare** | A friend's login failed because the name went into the Nickname field and the separate username field stayed empty. Now "Your name" plus an optional password. Railway adds its own proxy hops to X-Forwarded-For, so the per-IP lockout used one shared Railway address for everyone; it now uses CF-Connecting-IP, but only when the address that connected to Railway (second X-Forwarded-For entry from the end, written by Railway's edge) is a Cloudflare server. Otherwise that address itself is used, so going around Cloudflare doesn't allow faking an IP. |
| 2026-10-28 | **Fighting rules: health 100, body 34, head 100, respawn 3 s, protection 2 s, first to 10 kills** | Yoshi asked for lives, respawn and points. "Lives" became health (respawning makes a fixed number of lives pointless). The shooter's browser reports hits and the server checks them (both armed and alive, not protected, at most one hit per 120 ms, within 120 m). Line of sight is not checked: fine among friends, not cheat-proof. Explore players can't be hurt. Scores survive a reconnect until the next round. |
| 2026-10-28 | **Sessions in the database; all-time stats** | A deploy no longer logs everyone out: sessions are stored as a SHA-256 hash of the token (a leaked database can't be used to log in). Kills, deaths, headshots and round wins per account are added up in the `stats` table; the pause menu shows the leaderboard. Deleting a user deletes their sessions and stats. |
| 2026-10-28 | **Stored sessions are checked again on start** | Security review: logout, kick, password reset and user deletion now wait for the database delete (errors reach the admin). On start, player sessions only come back for users that still exist; admin sessions only while ADMIN_PASSWORD is unchanged (compared with a scrypt fingerprint in the `meta` table). A login that overlaps with a kick or delete is undone. |
| 2026-10-28 | **3D sound and footsteps made in code; settings in the browser** | Web Audio HRTF panners place other players' shots, steps and breaking glass; the listener follows the camera. Footsteps are filtered noise per floor material (no audio files to download). One step per stride (about 0.85 m walking, 1.2 m running). Settings live in localStorage; turning slows down in proportion while zoomed in. Vibration uses the Gamepad API's dual-rumble where the browser supports it. |
| 2026-10-28 | **Weapons as pickups; numbers shared with the server** | Rifle 26 per body hit (4 hits), shotgun 8 pellets of 15 (30 to the head), sniper 100 body / 200 head, pistol 34. Stats in `web/shared/weapons.json`, read by both the browser and the server, so damage can't drift apart. The server only accepts hits from weapons you picked up, at that weapon's fire rate and pellet count. Pickups (`web/shared/pickups.json`) are granted by the server within 2.5 m. |
| 2026-10-28 | **Loading screen** | Yoshi saw the start screen flicker between the street and the kitchen: those were the graphics test frames. A loading screen with a progress bar now covers loading and the test, then fades to the front of the house. |
| 2026-10-28 | **Server checks fire rate across weapons and movement speed** | Security review: a hit must come from the weapon in hand, with one shared next-shot time; position updates faster than 16 m/s are ignored (sprint is 10, a fall from the roof about 13), so pickups and hit range can't be reached by faking a teleport. Not checked: walls (a cheater could still pass through them at running speed). |
| 2026-10-28 | **Movement budget instead of a per-message limit** | Security review: the server keeps a movement budget per player that refills at 16 m/s (at most half a second stored), so sending many small updates can't add speed. A connection taken over from another device keeps its position; new players start on the street. Still accepted as a known limit: positions come from the browser and walls are not checked on the server, so a determined cheater can move through walls at running speed. Fine among friends; a server-side collision check would be the next step if needed. |

| 2026-10-28 | **Light bake: pipeline done, still a test setting** | `tools/bake/`: the game exports its static house meshes, Blender (Cycles, CPU) bakes sun, sky and bounced light into one 2048 texture (about 4 minutes at 512 samples), and the game draws the house as texture x baked light without real-time lighting. Outside surfaces stay real-time (baking them spent the texture on the street). Lessons: the game's faces are double-sided, so Blender must turn them outward; three.js divides a basic material's light map by pi; real indoor light is about 12 times darker than sunlit outside, so the texture stores the square root (more steps in the dark) and the eyes adapt 6 times indoors. Still noisy and dark in places, so it is a setting ("Baked lighting (test)") and real-time lighting stays the default. Next: denoise the bake (OIDN), and light probes for people and furniture. |
